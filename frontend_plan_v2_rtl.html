خطة الـ Frontend بالتفصيل

إنت المسؤول عن الـ web app كله. ده اللي هتعمله، واللي هتحتاجه من الفريق، والشكل النهائي.

الناتج النهائي في جملة

Web app بيعرض fire-activity calendar موحد من MODIS وVIIRS، ومعاه خريطة وcharts وpanel للـ anomalies والفترات الخطرة، وصفحة بتشرح المنهجية والـ validation. بيتنشر على رابط شغال (Vercel أو Netlify) ويتعرض في الـ demo.

الأدوات المقترحة

  • Vite + React (ولو متعود TypeScript استخدمه، هيساعدك مع الـ data contract).
  • MapLibre GL (عن طريق react-map-gl) للخريطة. مفتوح المصدر وبيتعامل مع كمية نقط كبيرة.
  • D3 للـ scales والألوان، والـ calendar heatmap تترسم SVG أو Canvas بإيدك. أحسن من مكتبة جاهزة لأنك هتتحكم في الشكل.
  • Recharts أو visx للـ line وbar charts.
  • Zustand أو Context للـ filters المشتركة (المنطقة، السنين، الـ sensor، الـ metric).
  • Tailwind أو CSS Variables للـ design tokens.

خطة الشغل بالترتيب

F0: Setup + Mock Data frontend/project-setup

  • مشروع Vite شغال، وهيكل فولدرات (components, features, data, hooks)، ومولّد mock data بنفس الـ contract.
  • خلصت لما: الـ app بيشتغل ببيانات وهمية.

F1: Design System frontend/design-tokens

  • الألوان والـ typography والـ spacing كـ tokens، والـ layout shell (top bar، filter rail، مساحة المحتوى)، ومكونات أساسية (Button, Select, Toggle, Card, Tooltip).

F2: Data Layer + Filters frontend/data-layer

  • Loaders للملفات، وstate مشترك للـ filters، وselectors (يوم/شهر/سنة)، وحالات loading وerror وempty.

F3: الـ Calendar (البطل) frontend/calendar-heatmap

  • Heatmap بالسنين، لون الخلية حسب الـ metric (count أو FRP)، وtooltip فيه تفاصيل MODIS vs VIIRS، وclick على يوم يفلتر الخريطة.

F4: الخريطة frontend/map-view

  • طبقة الـ grid heat، ونقط الـ recent، وtoggle لكل sensor، وtime slider مربوط بالـ calendar.

F5: Charts frontend/charts

  • Time series، وseasonality (شهر × سنة)، ومقارنة MODIS vs VIIRS.

F6: Anomalies + Risk + Audience Modes frontend/anomaly-panel

  • قايمة "الأيام الغريبة" والفترات الخطرة. وزر بيبدّل الـ view الافتراضي بين Responder (النشاط الأخير) وScientist (الداتا والمنهجية) وPlanner (الموسمية).

F7: Method & Validation frontend/method-page

  • شرح الـ harmonization بالخطوات، وscatter لـ MODIS vs VIIRS، والـ correlation والـ bias، وحدود المنهج بصراحة.

F8: Polish + Deploy frontend/polish

  • Responsive، وأداء (virtualization، وcanvas للنقط الكتير)، وaccessibility (تباين، keyboard focus، reduced motion)، ونشر، وسكريبت الـ demo.

مبادئ التصميم

  • الـ Calendar هو البطل: أكبر عنصر، وأول حاجة تتشاف. الباقي يخدمه.
  • حرارة بس بتتلون: الـ chrome كله navy ورمادي، فاللون العالي يبان فوراً.
  • حركة واحدة مقصودة: عند فتح الصفحة الخلايا بتتملي بالتتابع من اليسار لليمين. الباقي حركات بتحصل ردّاً على ضغطة بس.
  • صدق في الداتا: الـ legend وفيه وحدة القياس، ومكان بارز يوضح الـ sensor والـ confidence، وحالات empty واضحة ("مفيش حرائق مسجلة في الفترة دي").
  • الجودة الأساسية: تباين كويس، وfocus ظاهر للكيبورد، واحترام reduced motion، وشغال على الموبايل.
